# Local Context-Control Development/Calibration Study v1

**Status:** prospectively frozen implementation design; no local model
observations; no network use; no cloud spend.

**Protocol namespace:**
`context-build-artifact/local-context-control/v1`

**Frozen:** 2026-09-21

## Separation and permitted claims

This is a new provider-independent **development/calibration** study. It is not
the frozen TypeSafe final study, is not held-out AgentTrace evidence, and
cannot update, repair, reinterpret, authorize, or change the frozen TypeSafe
protocol based on its outcomes. Its package, schedule, receipts, raw outputs,
hashes, and result namespace are separate. `internal/studylocal` has no import
or call into `internal/studyfinal`.

The local study uses exactly 14 public-evidence bases and 118 clustered
conditions already registered as non-held-out material:

| Dataset | Role | Independent bases | Conditions |
|---|---|---:|---:|
| Distill | threshold development | 7 | 77 |
| LLMTraceFX | safety calibration | 7 | 41 |
| **Total** | development/calibration only | **14** | **118** |

AgentTrace's 7 bases, 32 conditions, IDs, evidence bytes, labels, outcomes,
receipts, and hashes are mechanically inadmissible. Public package validation
rejects an `AT-` base ID and any source path containing `agenttrace`,
`agent-trace`, `held_out`, or `held-out`.

## Research questions

1. Does deterministic Distill Lock compilation improve verified categorical
   decision correctness or reduce human-review burden compared with raw,
   deterministic source concatenation?
2. Are decision labels and cited evidence more repeatable with compiled
   context?
3. In a later amendment, can compiled context narrow the quality gap between
   the pinned local 4B target and a separately authorized scaling control?

The scaling control is disabled in v1. It requires a separate exact model,
artifact manifest, hardware target, clean preflight, schedule identity, and
explicit spending authorization. This implementation authorizes no CloudRift
or other cloud provisioning or spend.

## Context arms

Both arms receive the identical ordered source manifest and question text.

### Arm A: raw deterministic concatenation

Arm A validates each registered source path, UTF-8 bytes, and SHA-256, then
emits sources in the condition's frozen submitted order:

```text
--- BEGIN SOURCE: <relative-path> ---
<exact source bytes>
--- END SOURCE: <relative-path> ---
```

One LF follows the header. When the source does not end in LF, exactly one
wrapper LF precedes the footer. Arm A performs no line-ending or Unicode
normalization, de-duplication, chunking, ranking, filesystem enumeration,
selection, or truncation.

### Arm C: Distill Lock v0

Arm C materializes the same source allowlist and invokes the repository's
reviewed `pkg/lock` implementation. The frozen configuration is:

- `chunk_bytes = 1024`;
- `token_budget = 8192`;
- `metadata_removal = "none"`;
- UTF-8 NFC/LF normalization;
- exact normalized-content de-duplication;
- lexical whole-chunk selection; and
- verified bundle, lock, manifest, and checksum identities.

Arm C emits selected chunks in lexical source-path order, not Arm A's submitted
manifest order.

The package stores the exact `context.bundle.md` bytes and the lock, manifest,
configuration, and checksum digests for every Arm C condition. It does not
claim that model execution is deterministic.

## Corpus and independent adjudication

Every condition contains generated evidence bytes bound to a frozen public
source anchor. Ground truth is derived only by parsing the condition's
digest-verified evidence bytes. The derivation function cannot use the
filename, family name, model response, or model agreement. A changed evidence
byte requires a changed digest and produces a newly derived adjudication.

Two Distill base conditions contain deterministic synthetic padding to exercise the
real Lock chunking and whole-chunk budget mechanisms: 1,800 minimum generated bytes
for `distill-lock-golden-v0::base` and 40,000 for
`distill-lock-budget-whole-chunk::base`. The padding is corpus-digest-bound, contains
no adjudication-decisive key, and is part of the paired Arm A/Arm C input rather than
unreported production evidence.

Conditions remain clustered observations. The independent analysis unit is
the base. The 77 Distill conditions cannot receive more weight than the 41
LLMTraceFX conditions.

Condition order and within-condition arm order use frozen SHA-256 order keys.
Replicates are scheduled observations, never retries. Each schedule entry

states. A malformed model answer is retained as an observation and execution
continues. An adapter, integrity, timeout, or resource-monitor failure stops
the run, preserves an `aborted.json` record and the consumed one-time ledger,
and makes the whole run invalid; it is not counted as review burden or silently
retried.

The local ledger prevents concurrent and ordinary repeated consumption by locking,
reading, appending, and syncing the same no-follow inode while revalidating its
directory entry. Because all offline files remain owner-controlled, restoring a prior
filesystem snapshot cannot be cryptographically prevented locally. Such rollback is
outside the executable threat model, invalidates the study, and must be excluded by
independent custody of the authorization ledger and run namespace.

## Generation and response contract

- greedy MLX decoding with `make_sampler(temp=0)`;
- `temperature = 0`;
- recorded seed `20260921`;
- maximum 256 generated tokens per categorical question;
- exact checkpoint `chat_template.jinja`;
- `tokenize=true`, `add_generation_prompt=true`, `enable_thinking=false`;
- model EOS only; no client substring stop;
- raw generated bytes and token IDs are authoritative.

MLX seeded determinism is not claimed. The repeat subset measures realized
stability.

Each observation is one generation with one strict projection:

```json
{"answer":"<decision>|<sorted-cited-evidence-IDs>"}
```

The finite allowed enum is generated prospectively from
`accept|review|reject` and every sorted subset of that condition's registered
evidence IDs; `-` means no cited item. This keeps every observation to one
model generation and one categorical field without asking the model to produce
a free-form array. The vocabulary uses only public candidate decisions and
context-visible evidence IDs; it never consults adjudication, expected
decision, policy output, or a correct citation set. Every possible decision
and evidence subset remains available, including incorrect combinations.
There is no correctness-constraining decoder. Unsorted or duplicate citations
are not normalized into success. The wrapper adds `confidence: null` and
`confidence_basis: "unavailable"`. It parses once and classifies
`valid`, `invalid_json`, `schema_error`, `invalid_enum`, `trailing_text`, or
`duplicate_key`. It never extracts, repairs, retries, censors, or replaces a
response. Leading or trailing whitespace, including a trailing newline, is
`trailing_text`/`invalid_json` rather than being silently trimmed.

## Isolation and measurement

The required execution host is Apple M5 Pro arm64 with exactly 24 GiB on macOS
27.0 build 26A428. Before model load:

- both `vm_stat` available and `memory_pressure` free must be at least 25%;
- swap must be at most 12 GiB;
- free disk must be at least 20 GiB;
- no unrelated process may have RSS at or above 1 GiB;
- AC power, `caffeinate`, and a verified deny-network sandbox are required.

During each observation, sampled every two seconds:

- available/free memory must remain at least 15%;
- swap must remain at most 14 GiB and grow by at most 2 GiB;
- free disk must remain at least 12 GiB;
- adapter-process RSS must remain at most 12 GiB;
- MLX allocator peak must remain at most 8 GiB;
- the observation timeout is 12 minutes; and
- process-group cleanup must complete in 5 seconds.

The Go request-latency field uses monotonic elapsed time beginning after the
initial resource-preflight sample and ending after the adapter returns. The
continuing two-second resource monitor launches system probes concurrently
inside that interval. Because longer observations receive more probe
opportunities, per-arm request latency and its repeat dispersion are
descriptive environment-perturbed metrics, not a clean head-to-head
context-arm performance effect. Synchronized model timing and exact token
counts remain separately reported.

The runner stores synchronized load, tokenize, TTFT, decode, and total
durations; exact prompt and generated token IDs/counts; MLX active/cache/peak
allocator bytes; sampled process RSS; `vm_stat`, `memory_pressure`, and swap
observations; and derived tokens/second with numerator and denominator. Sampled
RSS is not called a true high-water mark. MLX allocator memory is not called
GPU memory. No fake Metal utilization, power, memory, bandwidth, or busy-time
counter is produced.

The 332-observation quality schedule is untraced. A PID-attributed Metal System
Trace is optional only under a separate, prospectively identified small
performance-subset phase. Traced latency cannot be pooled with untraced
latency, and unavailable or ambiguous Metal evidence cannot invalidate an
otherwise valid quality observation.

## Analysis

For each base, average replicate-1 correctness within arm and compute Arm C
minus Arm A. Report all 14 base deltas, their equal-weight mean and median, the
exact paired sign-flip distribution over all \(2^{14}\) assignments under its
exchangeability assumption, and leave-one-base-out sensitivity. Asymptotic
cluster-robust inference is not primary.

Review burden counts generated `review`/`reject` and malformed observations
routed to a human. Adapter/resource failure invalidates the run instead of
entering the burden denominator. Structural safety triggers remain separately
reported from generated route labels. Because confidence is unavailable, v1
selects no confidence threshold and reports no calibrated AURC. It evaluates
three prospectively fixed structural operating points on Distill only, in
strict-to-lenient order: `accept_with_all_evidence`,
`accept_with_any_evidence`, and `generated_accept`. The selected point is the
highest equal-base-weighted coverage with observed unsafe risk at most 0.15
and at least three accepted observations; ties retain the earlier, stricter
rule. Exactly that selected rule is evaluated once on LLMTraceFX. If no rule
qualifies, the result is `no-safe-auto-action` and no LLMTraceFX candidate
curve is exposed.

Repeat analysis reports all-three decision agreement, all-three route and
malformed agreement, evidence-ID Jaccard, and latency/output-token dispersion.
Failures remain in denominators.

Outcome classification is prospective:

- **positive:** equal-weight correctness improves by at least 0.05 without a
  material review-burden increase or unsafe-accept increase, or review burden
  falls by at least 0.05 without correctness falling by 0.05 or unsafe accepts
  increasing;
- **negative:** correctness falls by at least 0.05 or unsafe accepts increase
  by at least 0.05;
- **null:** neither threshold is crossed;
- **non-evaluable:** fewer than 80% of primary observations are valid; and
- **invalid:** any adapter/resource failure, or package, schedule, receipt,
  runtime, model, process, or
  authorization verification fails.

`invalid` is a hard verification error: the verification/summarization command exits
non-zero and emits no `ResultSummary`. It is not represented as a success-shaped
`outcome` field.

## Publication and execution boundary

Raw prompts, responses, stderr, receipts, model/runtime paths, and process data
are private and ignored. Only aggregate output may enter a separately reviewed
execution/result PR. The implementation PR does not run the 332 observations.
The `authorize` and `run` commands require an exact clean checkout whose HEAD
equals the reviewed merged main ref, so unmerged code cannot execute the study.
